The `process-orders-flow` in MuleSoft is scheduled to run every 60 seconds with a 10-second initial delay, processing orders from a queue. It consumes messages from the "orders-queue" and categorizes them into placed or cancelled orders. Placed orders are accumulated and sent to Salesforce, while cancelled orders are also accumulated and sent to Salesforce if they exist. The flow handles errors specifically for timeouts by logging and continuing the process. Additionally, it uses manual acknowledgments for message processing, ensuring messages are acknowledged only after successful processing or returned to the queue if not processed successfully.

&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;DEBUG: Messsage retrieved from queue | Logs a debug message indicating that a message has been successfully retrieved from the queue, including the current loop count from the variable `vars.counter`.
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Place or Cancel Order? | The "Place or Cancel Order?" choice component evaluates the `requestType` of each order payload. If `requestType` equals "placeOrder", it accumulates the order and its acknowledgment token into `placedOrders` and `placedOrdersAckToken` variables respectively. If `requestType` equals "cancelOrder", it accumulates the order and its acknowledgment token into `cancelledOrders` and `cancelledOrdersAckToken` variables respectively. If neither condition is met, it logs a default route message.
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Accumulate Placed Orders Ack Tokens | Accumulates acknowledgment tokens for placed orders into the `placedOrdersAckToken` variable by appending each new acknowledgment token received from the message attributes during order processing.
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Accumulate Cancelled Orders Ack Tokens | Accumulates acknowledgment tokens for cancelled orders into the `cancelledOrdersAckToken` variable by appending each new acknowledgment token received from the message attributes.
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;INFO: Default Route | Logs an informational message "Default Route" when none of the conditions in the choice router are met, effectively serving as a fallback or no-operation path.
Scatter-Gather | The `Scatter-Gather` component in the flow concurrently processes two routes: one for placed orders and another for cancelled orders. Each route checks if there are any orders to process and, if so, sends them to Salesforce using the `send-orders-to-salesforce-flow`. If there are no orders to process, it logs a default route message.
&nbsp;&nbsp;&nbsp;&nbsp;Place order exists? | The "Place order exists?" node checks if there are any placed orders stored in `vars.placedOrders`. If the list is not empty, it proceeds to set `vars.acktokens` and `vars.orders` with the acknowledgment tokens and orders respectively, and then calls the `send-orders-to-salesforce-flow` to process these orders. If the list is empty, it logs "Default Route".
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Placed Orders acktokens | Stores the acknowledgment tokens for successfully placed orders in the `acktokens` variable for further processing.
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Placed Orders | The "Placed Orders" flow component accumulates orders intended for placement into the `placedOrders` variable and their corresponding acknowledgment tokens into the `placedOrdersAckToken` variable, based on the condition that the `requestType` of the payload is "placeOrder".
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;send-orders-to-salesforce-flow | The `send-orders-to-salesforce-flow` sub-flow attempts to send order data to a Salesforce API endpoint. It retries the HTTP POST request up to three times if it fails due to connectivity or timeout issues. On successful request, it acknowledges the message in the queue; if the request fails after retries, it logs the error and pushes the error details to a Salesforce custom object table.
&nbsp;&nbsp;&nbsp;&nbsp;Cancelled order exists? | The "Cancelled order exists?" node checks if there are any cancelled orders accumulated in the `vars.cancelledOrders` variable. If the list is not empty, it proceeds to set the acknowledgement tokens and the list of cancelled orders as variables, and then calls the `send-orders-to-salesforce-flow` to process these orders. If the list is empty, it logs "Default Route".
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Cancelled Orders acktokens | Stores the acknowledgment tokens for cancelled orders in the variable `cancelledOrdersAckToken` for further processing.
&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Cancelled Orders | The "Cancelled Orders" node in the flow checks if there are any cancelled orders accumulated in the `vars.cancelledOrders` variable. If there are cancelled orders, it sets the acknowledgement tokens for these orders in `vars.cancelledOrdersAckToken` and sends the orders to Salesforce using the `send-orders-to-salesforce-flow`. If there are no cancelled orders, it logs "Default Route".
INFO: Scheduler flow completed | Logs the completion of the scheduler flow with the message "Scheduler flow completed." at INFO level.
